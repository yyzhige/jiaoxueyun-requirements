# 给后端与数据负责人的说明

本包只定义产品对象、可见状态、权限边界和行为结果，不代表 API、DTO、数据库或事件方案已经确定。

1. 学校是租户边界；身份、班级、学科和任课关系共同限定数据范围。
2. AI 初评、教师确认分和发布成绩必须是可区分、可追溯的不同业务状态。
3. 学生提交、评分、发布、修正、订正和计划调整需要保留版本与操作人。
4. 任课教师拥有本学科内容修改权；班主任拥有本班全科查看与协调权，但无默认跨学科修改权。
5. AI 查询、草稿和执行共享同一权限与审计，不允许用模型服务绕过业务授权。
6. `data-ownership-matrix.md` 是业务责任输入，不等于数据库表 Owner；任何权威对象都必须能追溯 Data ID 和源版本。
7. `field-option-catalog.md` 的固定 code、主数据来源、运行时集合、失效策略和权限过滤必须在接口合同中保持同义。
8. `data-flow-catalog.md` 定义业务 Flow；技术方案可以选择同步接口、异步事件或任务系统，但必须保持输入输出版本、幂等、部分失败、补偿和审计语义。
9. 每个接口或事件必须能追溯 Flow ID 与 Data ID；派生刷新失败不能反向伪造权威写入失败。
10. 技术设计前仍需关闭数据保留、图片存储、模型调用、通知、导入和导出等实现决策。
