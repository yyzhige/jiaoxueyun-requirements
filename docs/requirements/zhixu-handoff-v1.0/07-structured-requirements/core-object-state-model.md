# 核心对象与状态模型

本文件统一跨模块对象含义。模块 PRD 可增加局部状态，但不能把同名状态改成不同业务含义。

## 1. 核心对象关系

```text
School Space
  └─ Term
      ├─ Grade / Class / Course / Teaching Assignment
      ├─ Teacher Role / Student Membership
      └─ Assignment
          └─ Student Assignment
              └─ Submission Version
                  └─ Grading Version
                      └─ Result Release Version
                          ├─ Score Record
                          ├─ Correction Attempt
                          └─ Mastery Evidence
                              └─ Improvement Candidate
                                  └─ Improvement Plan Version
```

## 2. 状态总表

| 对象 | 状态 | 不允许的跳转 |
|---|---|---|
| 学校成员身份 | 待激活、有效、停用、失效 | 停用 / 失效不能继续访问业务 |
| 作业 | 草稿、待发布、进行中、已截止、批改中、待发布成绩、已完成 | 草稿不能产生学生提交；已有提交后不能静默改关键规则 |
| 学生作业 | 未开始、进行中、已提交、需补充、已退回、已截止 | 未发布作业不能进入未开始 |
| 提交版本 | 本地草稿、上传中、已生成、已被新版本替代 | 新版本不能删除旧版本 |
| AI 初评 | 排队中、识别中、初评中、待复核、无法判断、失败 | AI 状态不能直接跳到已发布 |
| 教师评分 | 待复核、已确认、已修正 | 未确认不能进入发布 |
| 发布成绩 | 待发布、发布中、已发布、部分失败、已修正 | 发布失败不能显示为学生已可见 |
| 订正 | 待订正、订正中、待复核、未通过、已通过、已关闭 | 已通过不覆盖首次成绩 |
| 掌握状态 | 数据不足、初步掌握、基本掌握、熟练掌握、需要巩固、明显薄弱 | 单一证据不能直接生成强状态 |
| 提升计划 | 候选、草稿、待协调、待确认、待开始、进行中、待评估、已完成、已调整 | 未经任课教师确认不能生效 |
| 导入批次 | 待上传、校验中、存在错误、待确认、导入中、部分成功、已完成 | 未校验不能导入 |
| 排课任务 | 草稿、校验中、计算中、存在冲突、待确认、已发布、已调整 | 有硬冲突不能发布 |
| AI 任务 | 理解中、待澄清、草稿已生成、待确认、执行中、成功、部分成功、失败、上下文失效 | 上下文失效不能继续执行 |

## 3. 分数语义

| 名称 | 产生者 | 学生可见 | 是否可进入正式成绩 |
|---|---|---|---|
| AI 建议分 | AI 初评 | 否 | 否 |
| 教师确认分 | 有评分权限的教师 | 否，发布前不可见 | 是，作为发布输入 |
| 发布分 | PUB-001 发布版本 | 是 | 是 |
| 修正分 | PUB-001 修正版本 | 是，生效后 | 是，历史版本保留 |
| 订正结果 | APP-002 | 是 | 默认不覆盖首次 / 发布分 |

## 4. 跨模块版本规则

1. 提交、评分、发布、修正、订正和计划都保留版本，不静默覆盖历史。
2. 下游模块引用上游版本；上游发生变化时，下游显示“依据已变化”并要求重新确认。
3. 人工确认优先于 AI 建议；后续系统只能提出重新评估，不静默覆盖人工决定。

## 5. 跨模块 Flow

对象关系只说明依赖方向，实际触发、输入版本、目标版本、责任交接、幂等、失败和补偿以 `data-flow-catalog.md` 为事实源。状态跳转与 Flow 冲突时必须阻断评审，不能由技术实现自行选择含义。
