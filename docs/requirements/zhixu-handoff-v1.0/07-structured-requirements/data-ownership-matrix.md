# 数据 Owner 与责任矩阵

本文件是业务数据责任的中央事实源。权限矩阵回答“谁能做什么”，本文件回答“数据错误时谁必须负责推动纠正、谁有权确认正式值”。

## 1. 责任角色定义

| 角色 | 定义 |
|---|---|
| 最终 Owner | 对对象定义、正确性、变更规则和生命周期承担最终责任的唯一业务角色 |
| Steward | 负责日常维护、质量检查、异常处理和用户协同的角色 |
| 产生者 | 创建原始记录的人或系统；产生者不自动成为最终 Owner |
| 确认 / 发布者 | 使草稿、建议或记录成为正式业务值的角色 |
| 事实源 | 发生冲突时被视为权威的业务对象或模块 |

责任约束：

1. AI、求解器、缓存、统计视图和导出文件不成为最终 Owner。
2. 任课教师只对所教学科负责；班主任对本班全科协调记录负责，但不接管学科判断。
3. 学生对本人作答、提交和反馈负责；成绩、掌握状态和学科计划仍由任课教师确认。
4. 学校管理员负责身份、授权和审计治理，不默认拥有教学专业判断。
5. 教务负责学期、班级、课程、任课、考试和课表等校级教学组织数据。

| DAT-GOV-01 | Permission Policy 权限策略 | 学校管理员 | 学校管理员 | 学校管理员配置 | 学校管理员 | GOV-001 策略版本 | ACC、全业务模块、AI、CLI | 管理员配置能力不等于默认查看全部教学明细 |
| DAT-GOV-02 | Temporary Access Grant 临时敏感访问授权 | 学校管理员 | 指定审批人 | 申请人 | 学校管理员 / 指定审批人 | GOV-001 授权版本 | 权限执行、审计 | 必须限定对象、范围、动作、有效期和原因 |
| DAT-GOV-03 | Audit Event 审计事件 | 学校管理员 | 审计人员 | Web、App、AI、CLI、系统任务 | 不适用，事件只追加 | GOV-001 审计日志 | 学校管理员、授权审计角色 | 审计不可由业务用户修改或删除；展示按权限脱敏 |
| DAT-CLI-01 | CLI Session CLI 会话上下文 | 当前用户 | 当前用户 | 当前用户 | 系统按授权校验 | CLI-001 会话 | 当前用户、AI | 无明确学校和身份时不得执行修改；旧上下文可失效 |
| DAT-CLI-02 | Authorized Automation 自动化授权 | 学校管理员 | 授权管理员 / 自动化负责人 | 管理员配置 | 学校管理员 / 指定审批人 | CLI-001 自动化授权版本 | CLI、GOV | 必须限定命令域、学校、数据范围、动作、有效期和最大影响量 |

## 7. 派生视图与导出责任

以下对象不建立独立业务 Owner，必须携带源对象版本并继承源对象责任：

| 派生对象 | 责任规则 |
|---|---|
| Teacher Work Queue / Today Learning Feed | 每条任务继承作业、提交、成绩、订正或计划的 Owner |
| Gradebook View / Student Learning Profile | 每个成绩、学情和计划单元继承对应源对象 Owner |
| Class Coordination Summary | 学科事实继承任课教师；班主任只拥有协调记录 |
| Error Collection | 错题内容继承 Error Item，筛选和分组不改变责任 |
| AI Query Result / CLI Query Result | 查询结果继承源对象，不因被 AI 或 CLI 展示而转移责任 |
| Export File | 导出人对文件保管负责，业务值仍由源对象 Owner 负责 |

## 8. 字段级责任例外

| 字段类别 | 例外规则 |
|---|---|
| 学生原始作答、图片、学生反馈 | Owner 为学生本人；教师只能评价或按合规要求处理 |
| AI 识别文本、建议分、建议标签 | AI 是产生者；对应任课教师对采用、修正或拒绝负责 |
| 教师私密备注 | Owner 为记录教师；不可作为学生可见反馈或跨角色默认共享 |
| 班主任协调意见 | Owner 为班主任；不能改写任课教师的学科目标、评分或掌握判断 |
| 审计 before / after | 继承被操作对象责任；审计记录本身由学校管理员治理 |

## 9. 验收规则

1. 新增权威业务对象时必须先分配 Data ID 和唯一最终 Owner。
2. PRD 中出现“AI 自动确认”“系统自动负责”或“班主任可修改全科判断”时必须阻断评审。
3. 任课教师变更后，新教师接管当前未完成工作需显式确认，历史版本保留原 Owner。
4. 派生视图必须能追溯到源 Data ID 和源版本，不能保存为另一份互相冲突的事实。
