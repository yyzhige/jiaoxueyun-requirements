> 端口：教师 Web

| 项目 | 内容 |
|---|---|
| 已确认 | 工作台以待处理教学任务为核心，不做营销式首页。 |
| 已确认 | 任课教师看本学科；班主任看本班全学科任务和风险摘要。 |

## 1. 页面、对象与目标

| 页面 / 载体 | 对象 | Node ID | Prototype ID |
|---|---|---|---|
| 教师工作台 | Teacher Work Queue | TEA-N10 | TEA-P01 |
| 待处理任务列表 | Assignment / Student Follow-up | TEA-N20 | TEA-P02 |
| 班主任全科摘要 | Class Coordination Summary | TEA-N30 | TEA-P03 |

业务目标：教师进入系统后在一个屏幕内识别“现在最需要处理什么”，并能进入对应业务模块继续完成，而不是重新逐层查找班级和作业。

## 2. 关键业务规则

1. 工作台数据必须绑定当前学校、身份和学期。
2. 任课教师统计范围为有效任课关系下的班级和学科。
3. 班主任摘要可以读取本班全学科任务量、缺交与关注事件，但不能从工作台直接改其他学科评分或计划内容。
4. 待办按“阻断学生后续行动 > 临近截止 > 批量效率”排序；允许用户切换为按班级或时间。
5. 已完成任务从主待办移除，保留在最近完成记录。
6. 数据不足或模块异常时，卡片显示局部错误，不让整个工作台不可用。
7. 工作台不使用公开班级排名作为主指标。

## 3. 信息与字段

| 区域 | 字段 | 规则 |
|---|---|---|
| 当前上下文 | 学校、身份、学期 | 固定展示，可进入 ACC-001 切换器 |
| 今日概览 | 课程数、截止作业、待批改、待发布 | 数量可点击进入筛选后的列表 |
| 待处理 | 类型、对象、班级、学科、截止 / 产生时间、建议动作 | 只展示当前权限范围 |
| 快捷操作 | 创建作业、进入批改、查看成绩册、查看学生 | 根据身份与权限显示 |
| 班主任摘要 | 全科任务量、连续缺交、订正未通过、计划冲突 | 仅班主任身份可见 |
| 最近完成 | 完成事项、操作人、完成时间 | 默认展示最近 7 天 |

## 4. 交互与状态

```text
进入教师工作台
→ 加载当前身份摘要
→ 教师查看待办
→ 点击数量或待办进入带上下文的下游模块
→ 下游完成后返回并局部刷新
```

| 状态 | 页面行为 |
|---|---|
| Loading | 固定骨架，不显示虚假 0 值 |
| Ready | 展示摘要、待办和快捷操作 |
| Partial Error | 失败卡片显示重试，其余区域可用 |
| Empty | 显示今日无待办，并提供创建作业或查看课程入口 |
| Context Changed | 清空旧数据，重新加载新身份范围 |

## 5. 需求章节

### 5.1 教师工作台首页

- 顶部显示当前日期、学校、身份和学期，不使用超大欢迎语占据首屏。
- 第一屏必须完整显示今日概览、最高优先级待办和至少一个快捷操作。
- 数量卡点击后携带当前班级、学科和状态筛选，不进入无上下文全局列表。

### 5.2 待处理任务

- 支持类型筛选：待批改、待复核、待发布、学生补交 / 订正、计划待确认。
- 每条任务显示产生原因和下一步动作；不能只显示“异常”。
- 完成后返回工作台，当前条目消失并刷新相关计数。

### 5.3 班主任全科摘要

- 展示本班各学科未来 7 天任务量和预计总用时。
- 对连续缺交、多学科任务堆积和计划冲突生成可关闭事件提醒。
- 点击学科进入只读摘要；需要修改学科内容时进入对应任课教师流程或发起协调。

## 6. 权限矩阵

| 能力 | 任课教师 | 班主任 | 教务 |
|---|---|---|---|
| 本学科待办 | 查看并处理 | 仅兼任该学科时处理 | 不在教师工作台处理 |
| 本班全科摘要 | 否 | 查看与协调 | 由教务工作台承接 |
| 创建作业 | 对所教学科 | 仅对所教学科 | 否 |
| 修改他科评分 / 计划 | 否 | 否 | 否 |

## 7. 验收与评估

| ID | 验收标准 |
|---|---|
| TEA-AC-01 | 工作台计数与下钻结果一致，且携带正确筛选上下文。 |
| TEA-AC-02 | 任课教师看不到非任教学科学生明细。 |
| TEA-AC-03 | 班主任能查看本班全科摘要，但不能修改他科评分与计划内容。 |
| TEA-AC-04 | 一个卡片加载失败不阻断其他卡片和快捷操作。 |
| TEA-AC-05 | 切换身份后旧身份待办立即清除。 |
| TEA-AC-06 | 下游操作完成后返回，计数和任务状态局部刷新。 |

评估指标：教师从登录到开始首个有效任务的中位时长、待办点击到完成的转化率、工作台与下游计数不一致率。

## 数据责任与选择型字段合同

- 本模块的工作队列和班主任摘要是派生视图，不建立独立数据 Owner；每条任务继承作业、提交、批改、发布、跟进或计划源对象的 Owner。
- 班主任只拥有本班全科协调记录，不拥有跨学科评分、掌握状态和学科计划。
- 选择型字段：`TEA-F001` 至 `TEA-F005`，覆盖任务类型、班级、学科、时间范围和协调班级。
- 中央事实源：[数据 Owner 矩阵](../07-structured-requirements/data-ownership-matrix.md)；[字段与选项字典](../07-structured-requirements/field-option-catalog.md)。

## 数据流转合同

- 参与 Flow：`DF-003`、`DF-005`、`DF-006`、`DF-012`、`DF-013`。
- 输入：作业、提交、复核、发布、跟进和计划源对象状态；输出：Teacher Work Queue 与班主任协调摘要的派生刷新。
- 本模块不产生第二份权威任务，只根据源版本生成入口、计数和待办；下游成功后局部刷新。
- 中央事实源：[跨模块数据流转合同](../07-structured-requirements/data-flow-catalog.md)。
