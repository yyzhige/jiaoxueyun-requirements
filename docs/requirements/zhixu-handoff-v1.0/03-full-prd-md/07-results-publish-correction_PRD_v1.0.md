## 2. 关键业务规则

1. 只有教师确认分可以进入发布；AI 建议分不可直接发布。
2. 发布前检查未处理主观题、低置信、无法判断、未交和版本过期提交。
3. 发布预览展示班级、学生数、分数范围、反馈开放内容、答案 / 解析开放时间和通知范围。
4. 发布形成不可变 Release Version；学生只看到当前有效发布版本。
5. 公开反馈、私密备注和内部 AI 依据必须分离，私密内容永不向学生开放。
6. 分批发布时，学生是否可见由本人发布状态决定，未发布学生不看到班级统计。
7. 成绩修正记录原值、新值、原因、操作人、时间和学生可见说明。
8. 修正后生成新发布版本；历史版本不可删除。
9. 订正结果进入知识点证据和订正记录，默认不覆盖首次成绩；若学校启用替代规则需另行评审。
10. 发布和批量通知失败必须返回学生级结果，不允许状态不明。

## 4. 需求章节

### 4.1 发布准备

- 按学生列出确认状态、分数、未交 / 迟交和反馈完整度。
- 阻断项与非阻断提醒分开；未交可以按规则发布为缺交状态，未复核主观题必须阻断。
- 教师可返回 GRD-001 处理问题，返回后刷新当前列表。

### 4.2 发布预览与确认

- 展示影响人数、学生可见内容和发送通知样例。
- 高风险确认按钮使用明确动作名称“发布成绩与反馈”，不使用“确定”。
- 发布期间可离开页面，完成后通知教师结果。

### 4.3 学生可见结果

- 学生看到本人当前发布分、题目反馈、教师公开评语和订正入口。
- 不展示 AI 置信度、内部评分依据、教师私密备注和其他学生成绩。
- 成绩被修正时显示更新时间与学校允许公开的说明。

### 4.4 成绩修正

- 只能由有该学科评分权限的教师或授权教务发起。
- 修改单题分时自动重算总分并展示差值。
- 保存前要求选择或填写原因；发布新版本前预览学生影响。

## 6. 验收与评估

| ID | 验收标准 |
|---|---|
| PUB-AC-01 | 未经教师确认的结果无法进入发布。 |
| PUB-AC-02 | 未复核主观题和版本过期提交阻断发布。 |
| PUB-AC-03 | 学生只能看到本人已发布版本与公开反馈。 |
| PUB-AC-04 | 私密备注和 AI 内部依据不进入学生结果。 |
| PUB-AC-05 | 成绩修正保留原值、新值、原因和操作人。 |
| PUB-AC-06 | 修正后学生看到新版本，历史版本仍可审计。 |
| PUB-AC-07 | 订正结果默认不覆盖首次成绩。 |
| PUB-AC-08 | 发布部分失败有学生级明细并可安全重试。 |

评估指标：发布前阻断率、发布失败率、发布后 24 小时内修正率、学生反馈查看率。

## 数据责任与选择型字段合同

- 权威对象：`DAT-PUB-01` 发布版本、`DAT-PUB-02` 学生当前可见结果、`DAT-PUB-03` 成绩修正。
