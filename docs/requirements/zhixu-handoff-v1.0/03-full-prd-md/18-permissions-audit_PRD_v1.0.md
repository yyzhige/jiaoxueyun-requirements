## 2. 权限模型

```text
有效权限 = 角色能力 × 当前学校 × 当前身份 × 数据范围 × 对象状态
```

数据范围至少包含学校、学期、年级、班级、学科、任课关系和本人对象。前端隐藏入口只改善体验，服务端仍需逐请求验证。

## 3. 关键业务规则

1. 学校间数据严格隔离，跨学校访问默认拒绝。
2. 一个账号可有多个身份，但每次业务操作只使用当前身份；不得合并身份取得更大权限。
3. 任课教师读写所教班级和学科；班主任查看本班全科并协调；教务按职责范围查看；管理员默认只配置。
4. 学生只能访问本人已发布作业、成绩、反馈和计划。
5. 成绩发布 / 修正、权限变更、数据导出、组织导入、调课、批量通知和 AI 执行必须审计。
6. 审计事件记录谁、何时、在哪个学校与身份、对什么对象、执行什么动作、结果与原因。
7. 普通用户不能修改或删除审计记录；更正审计说明采用追加记录。
8. 敏感访问授权包含申请人、原因、范围、有效期、审批人和实际访问记录，到期自动失效。
9. AI、CLI 和业务页面调用同一权限语义，不存在“AI 专用更大权限”。
10. 权限撤销后新请求立即失败，已打开页面的敏感内容应清除或重新认证。

## 6. 需求章节

### 6.1 角色分配与权限预览

- 管理员分配身份时选择有效期与数据范围；系统展示将获得的能力摘要。
- 保存前预览受影响用户、班级和数据范围；高权限角色要求二次确认。
- 用户可在 ACC-001 身份选择页看到自己的范围摘要。

### 6.2 权限拒绝

- 拒绝提示说明当前身份无权执行，并提供切换身份或联系管理员入口。
- 不向无权限用户泄露敏感对象是否存在、姓名或数量。

### 6.3 审计查询与敏感访问

- 支持学校、用户、身份、对象、动作、来源、结果和时间筛选。
- 审计详情显示结构化变化和关联业务对象。
- 临时访问审批到期后自动撤销，并可查看期间实际访问明细。

## 7. 验收与评估

| ID | 验收标准 |
|---|---|
| GOV-AC-01 | 学校、身份和数据范围任一不匹配时拒绝访问。 |
| GOV-AC-02 | 班主任全科查看权不产生他科学科修改权。 |
| GOV-AC-03 | 学校管理员默认无法浏览全部学生教学明细。 |
| GOV-AC-04 | 权限撤销后缓存页面和新请求均不能继续访问。 |
| GOV-AC-05 | Web、App、AI 和 CLI 使用一致权限结果。 |
| GOV-AC-06 | 高风险操作产生完整审计事件。 |
| GOV-AC-07 | 临时敏感访问到期自动失效并记录实际访问。 |
| GOV-AC-08 | 无权限提示不泄露对象存在性和敏感数量。 |

评估指标：越权事件数、错误拒绝率、权限工单数、审计完整率、临时授权逾期数。

## 8. 就绪

本模块是所有 P0 模块的横向门禁。教务临时访问岗位待确认；尚未完成产品确认。

## 数据责任与选择型字段合同

- 权威对象：`DAT-GOV-01` 权限策略、`DAT-GOV-02` 临时授权、`DAT-GOV-03` 审计事件；身份范围引用 `DAT-ACC-03`。
- Owner 边界：学校管理员负责治理和审计完整性，但不因管理员身份默认获得全部教学明细浏览权。
- 选择型字段：`GOV-F001` 至 `GOV-F011`，覆盖用户、身份、范围、审计对象、动作、来源、结果、时间和临时授权时长。
- 中央事实源：[数据 Owner 矩阵](../07-structured-requirements/data-ownership-matrix.md)；[字段与选项字典](../07-structured-requirements/field-option-catalog.md)。

## 数据流转合同

- 参与 Flow：`DF-001`、`DF-002` 权限输入，`DF-013` 责任交接，`DF-014`、`DF-015` 受控执行，`DF-016` 审计，`DF-202`、`DF-301` 长期高风险流。
- 输入：角色、范围、临时授权和各业务操作 before / after；输出：`DAT-GOV-01~03`、拒绝结果与审计引用。
- 权限、版本或强制审计失败时失败关闭；审计只追加，补偿和撤销产生新事件。
- 中央事实源：[跨模块数据流转合同](../07-structured-requirements/data-flow-catalog.md)。
