## 2. 关键业务规则

1. 首页只展示当前学生本人、当前学校和当前学期可见内容。
2. 任务优先级依次考虑已逾期 / 即将截止、教师退回、待订正、新反馈、正式作业、提升任务和复习建议。
3. 每项任务展示学科、动作、截止、预计用时、进度和产生原因。
4. 已完成任务折叠到今日完成，不持续占用首屏。
5. 学生不看到未发布成绩、教师私密备注、AI 内部状态和其他学生数据。
6. 首页不展示完整班级排名；可以展示本人趋势、完成记录和阶段目标。
7. 无正式任务时可展示错题回顾或复习建议，但必须与正式作业区分。
8. AI 学习助手继承当前学校、学生和页面上下文，不能替学生提交、修改成绩或自动完成任务。

## 3. 信息结构

| 分区 | 内容 |
|---|---|
| 顶部 | 日期、当前学校、问候、通知入口 |
| 首要行动 | 一条最高优先级任务及开始按钮 |
| 今日任务 | 作业、订正、提升任务，按优先级分组 |
| 新反馈 | 新发布成绩、教师回复和计划调整 |
| 今日完成 | 已完成项折叠摘要 |
| 学习助手 | 悬浮入口，显示未读或待确认状态 |

## 4. 状态与交互

| 状态 | 行为 |
|---|---|
| Ready | 展示首要行动与任务分组 |
| Empty | 展示今日无正式任务、课程与复习建议 |
| Partial Error | 失败分区可重试，已加载任务仍可进入 |
| Offline | 展示本地可继续任务并标明同步状态 |
| Context Changed | 切换学校后清空旧任务和助手上下文 |

点击任务进入对应模块并携带 taskId；返回首页后局部刷新当前任务，不重新排序已完成记录导致跳动。

## 5. 需求章节

### 5.1 今日学习

- 第一屏显示当前最重要动作、截止和预计用时。
- 同一作业的“完成作业”和“完成订正”是不同任务，不合并为模糊状态。
- 逾期任务展示学校补交规则和可执行动作。

### 5.2 任务卡

- 操作按钮使用明确动词：开始、继续、补充、查看反馈、开始订正、继续提升。
- 学科用文字与图标共同表达，不能只靠颜色。
- 预计用时为参考，不用于对学生施压或教师绩效。

### 5.3 空状态与通知

- 无任务时不制造虚假紧迫感；显示今日课程、错题回顾和下一个截止任务。
- 新反馈卡只显示已发布内容；点击进入 APP-002 或相关计划。

## 6. 验收与评估

| ID | 验收标准 |
|---|---|
| APP1-AC-01 | 首页任务均属于当前学生、学校和学期。 |
| APP1-AC-02 | 最高优先级任务的截止、原因和动作清晰可见。 |
| APP1-AC-03 | 已完成任务折叠，不持续占用主区域。 |
| APP1-AC-04 | 无任务时展示真实空状态与可选复习建议。 |
| APP1-AC-05 | 首页不展示完整班级排名或其他学生数据。 |
| APP1-AC-06 | 离线时可继续本地任务并明确同步状态。 |
| APP1-AC-07 | 切换学校后不保留旧学校任务和 AI 引用。 |

评估指标：学生从打开 App 到开始任务的中位时长、逾期任务进入率、空状态误导反馈数。

## 数据责任与选择型字段合同

- Today Learning Feed 是派生视图，不建立独立数据 Owner；每条卡片继承作业发布、提交、成绩、订正或提升任务的 Owner。
- 学生只负责打开、执行和反馈本人任务，不得通过首页修改源任务类型与正式优先级。
- 选择型字段：`APP1-F001`、`APP1-F002`；本模块首轮没有可编辑下拉，学校 / 身份 / 学期通过 ACC-001 切换。
- 中央事实源：[数据 Owner 矩阵](../07-structured-requirements/data-ownership-matrix.md)；[字段与选项字典](../07-structured-requirements/field-option-catalog.md)。

## 数据流转合同

- 参与 Flow：`DF-003`、`DF-004`、`DF-007`、`DF-009`、`DF-011`、`DF-012`、`DF-015`。
- 输入：已发布作业、提交状态、已发布反馈、订正和提升任务；输出：Today Learning Feed 派生刷新及学生执行入口。
- 首页不写源任务状态；动作完成后按源版本局部刷新，上下文切换后清空旧学校任务和引用。
- 中央事实源：[跨模块数据流转合同](../07-structured-requirements/data-flow-catalog.md)。
