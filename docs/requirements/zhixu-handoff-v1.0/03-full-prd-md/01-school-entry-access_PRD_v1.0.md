> 优先级：P0
> 当前阶段：产品评审稿
> 端口：教师 / 教务 Web、学生 App
> 关联基线：TENANT-001、AUTH-001、AUTH-002

## 0. 产品评审摘要

| 项目 | 内容 |
|---|---|
| 已确认 | 用户先选择学校，再登录或激活账号，再选择当前身份；学校是租户边界。 |
| 已确认 | 一个账号可拥有多个学校与多个身份；切换后页面数据和 AI 上下文同步切换。 |
| 本模块拥有 | 学校查找、学校确认、登录 / 激活、身份选择、学期上下文和切换入口。 |
| 本模块不拥有 | 学校入驻审核、统一身份平台、完整账号安全策略、组织导入内部规则。 |
| 待产品确认 | 试点学生首次激活采用“学号 + 初始口令”还是“学号 + 个人验证信息”。 |

## 1. PRD 主文档

### 1.0 页面 / 入口 / 对象盘点

| 端口 | 页面 | 页面类型 | 业务对象 / 边界 | Node ID | Prototype ID |
|---|---|---|---|---|---|
| Web / App | 选择学校 | 搜索选择页 | School Space | ACC-N10 | ACC-P01 |
| Web / App | 登录或激活 | 表单页 | Account Membership | ACC-N20 | ACC-P02 |
| Web / App | 选择身份 | 选择页 | Role Assignment | ACC-N30 | ACC-P03 |
| Web / App | 上下文切换器 | 全局菜单 / sheet | School + Role + Term | ACC-N40 | ACC-P04 |

### 1.1 业务目标

1. 保证用户在读取任何学生、作业或成绩数据前已经进入明确学校空间。
2. 将账号身份与当前工作身份分开，避免多身份用户看到错误导航或数据范围。
3. 为 AI 对话、审计和后续业务模块提供可验证的学校、身份和学期上下文。

### 1.2 非范围

| 场景 | 本期结论 |
|---|---|
| 游客浏览学校公开信息 | 不纳入。 |
| 跨学校合并成绩或学生档案 | 禁止。 |
| 微信、QQ 等社会化登录 | 不纳入试点。 |
| 区域统一身份、教育专网 SSO | 后续技术与商务评估。 |
| 平台运营创建学校 | 由学校入驻模块承接。 |

### 1.3 关键业务规则

1. 未选择学校时不得展示账号在其他学校中的身份、班级或教学数据。
2. 学校搜索结果只显示名称、地区、办学类型和校徽，不显示成员或学生信息。
3. 登录凭据验证成功后，只返回该账号在当前学校中的有效身份。
4. 身份被撤销、停用或超出有效期时不展示；正在使用时被撤销，应在下一次请求或推送后强制退出该身份。
5. 学期默认选择学校当前学期；历史学期为只读时必须明确标识。
6. 切换学校必须结束当前可执行 AI 上下文、清空未提交的跨学校批量操作并重新校验身份。
7. 切换身份保留同一学校，但导航、默认班级、学科和可执行动作必须重新计算。
8. 学生账号默认只有学生身份；教务和学校管理员身份只能由授权管理员授予。
9. 学校不存在、未加入或账号异常时，提供联系学校管理员的明确路径，不允许自动进入其他学校。

### 1.4 字段表

| 字段 | 说明 | 必填 | 默认 / 校验 | 可见范围 |
|---|---|---|---|---|
| 学校关键词 | 学校名称或学校代码 | 否 | 至少 2 个字符后搜索 | 全部用户 |
| 地区 | 省 / 市 / 区县 | 否 | 试点默认河北省石家庄市 | 全部用户 |
| 学校 | 目标 School Space | 是 | 必须为可用学校 | 全部用户 |
| 账号标识 | 手机号、工号或学号 | 是 | 由学校配置允许类型 | 当前学校 |
| 激活凭据 | 初始口令或验证信息 | 首次激活必填 | 具体方式待确认 | 当前学校 |
| 当前身份 | 学生、任课教师、班主任、教务、学校管理员 | 是 | 仅有效授权 | 当前学校 |
| 当前学期 | 学校学期 | 是 | 默认当前学期 | 当前学校 |

## 2. 总业务流程

```text
打开产品
→ 搜索并选择学校
→ 确认学校信息
→ 登录或首次激活
→ 加载当前学校有效身份
→ 单身份直接进入 / 多身份选择
→ 确认当前学期
→ 进入角色首页
```

### 2.1 状态矩阵

| 状态 | 可见内容 | 可执行操作 | 退出条件 |
|---|---|---|---|
| 未选学校 | 学校搜索 | 搜索、选择 | 确认学校 |
| 学校已选 | 学校摘要、登录表单 | 登录、激活、返回 | 凭据成功或返回 |
| 待选身份 | 有效身份列表 | 选择身份 | 身份校验通过 |
| 上下文有效 | 当前学校 / 身份 / 学期 | 进入业务、切换 | 退出或授权失效 |
| 授权失效 | 原因与联系入口 | 返回身份选择、退出 | 获得新授权 |
| 服务异常 | 不展示业务数据 | 重试、退出 | 请求成功 |

### 2.2 权限与隔离矩阵

| 场景 | 规则 |
|---|---|
| 同账号多学校 | 学校间会话、缓存、AI 上下文和最近对象不得互相引用。 |
| 同学校多身份 | 数据按当前身份重新授权；不可把班主任全科范围带入任课教师身份。 |
| 历史学期 | 只读或可编辑由学校规则决定，页面必须显示当前模式。 |
| 无身份 | 不进入角色首页，不展示任何业务数据。 |

## 3. 需求章节

### 3.1 选择学校

- 搜索结果支持名称与学校代码；试点地区默认石家庄，但允许清除地区筛选。
- 选择后展示学校全称、地区、办学类型和校徽供用户二次确认。
- 最近使用学校只在本机展示，不代表仍有有效授权。
- 无结果时提供检查关键词和联系学校管理员的提示，不提供“创建学校”。

### 3.2 登录与激活

- 登录页必须显示当前学校，用户可以返回更换学校。
- 已激活账号走登录；未激活账号进入学校配置的激活流程。
- 连续失败后按学校安全策略限制重试，并提供找回或管理员联系入口。
- 激活完成后直接进入身份加载，不要求重新搜索学校。

### 3.3 身份与学期选择

- 每个身份项显示角色、数据范围摘要和有效期；教师身份显示主要班级 / 学科摘要。
- 单一有效身份可自动进入，但全局切换器仍可见。
- 历史学期必须标注“历史”及只读状态。

### 3.4 上下文切换

- 切换前如存在未提交表单，提示保存草稿或放弃。
- 切换成功后返回新身份首页，不停留在旧身份无权限的深层页面。
- AI 面板显示当前学校与身份；旧会话只可查看，不可继续执行。

## 4. 验收与评估

| ID | 验收标准 | 验证方式 |
|---|---|---|
| ACC-AC-01 | 未选择学校无法进入登录后的业务页面。 | 路由与权限测试 |
| ACC-AC-02 | 多学校账号切换后不出现旧学校班级、学生、作业或 AI 引用。 | 跨租户负例 |
| ACC-AC-03 | 多身份账号的导航和数据范围随身份变化。 | 角色矩阵测试 |
| ACC-AC-04 | 身份撤销后不能继续访问缓存页面或执行 API。 | 权限撤销测试 |
| ACC-AC-05 | 学生首次激活失败可理解且不泄露账号是否存在。 | 文案与安全测试 |
| ACC-AC-06 | 历史学期的只读状态在入口和页面持续可见。 | 状态测试 |

评估指标：学校选择成功率、首次激活完成率、因错误学校 / 身份产生的支持工单数、跨学校越权事件数。

## 数据责任与选择型字段合同

- 权威对象：`DAT-ACC-01` 至 `DAT-ACC-04`，学期引用 `DAT-ORG-01`。
- Owner 边界：学校管理员负责学校、成员与授权；当前用户只负责本人的上下文选择，不能通过切换器改变实际授权。
- 选择型字段：`ACC-F001` 至 `ACC-F008`，覆盖地区、学校、账号类型、激活方式、身份和学期。
- 中央事实源：[数据 Owner 矩阵](../07-structured-requirements/data-ownership-matrix.md)；[字段与选项字典](../07-structured-requirements/field-option-catalog.md)。

## 数据流转合同

- 参与 Flow：`DF-001` 学校 / 身份 / 学期上下文建立，`DF-015` 上下文切换与失效，敏感动作进入 `DF-016`。
- 输入：`DAT-ACC-01~03`、`DAT-ORG-01` 当前有效版本；输出：`DAT-ACC-04` 和全端上下文刷新。
- 本模块负责授权校验、上下文建立和失效，不负责修改组织主数据或业务对象 Owner。
- 中央事实源：[跨模块数据流转合同](../07-structured-requirements/data-flow-catalog.md)。
