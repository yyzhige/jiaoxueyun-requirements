## 2. 关键业务规则

1. 排课输入来自当前学期课程、班级、教师、教学任务、教室和校历。
2. 硬约束冲突必须阻断发布；软约束冲突展示影响并允许教务确认接受。
3. 每条冲突包含原因、影响教师 / 班级 / 教室、相关约束和可行调整建议。
4. 系统可生成多个候选方案，必须显示评估口径，不能只给单一“最优”。
5. 人工调整实时检查新增冲突，不允许静默破坏硬约束。
6. 发布前按教师、班级和教室三个视角预览。
7. 发布形成课表版本；调课与代课保留原安排、新安排、原因、操作人和通知范围。
8. 未发布草稿不进入学生与教师正式课表。

## 5. 需求章节

### 5.1 输入与约束

- 排课前检查缺教师、缺班级、缺周课时和无可用教室等基础错误。
- 约束显示来源、适用范围、优先级和是否允许人工覆盖。

### 5.2 候选与冲突

- 候选方案显示未满足软约束数量、教师空档、班级分布和教室使用摘要。
- 冲突可按对象定位到课表格；建议只作为调整候选。

### 5.3 调整与发布

- 拖动课程前预览目标时段影响；确认后更新冲突列表。
- 发布确认展示教师、班级、教室数量和将发送的通知范围。

### 5.4 调课与代课

- 选择原课、变更类型、目标时段 / 代课教师、原因和通知范围。
- 已生效变更进入新版本，不直接覆盖审计历史。

## 6. 验收候选

| ID | 验收标准 |
|---|---|
| SCH-AC-01 | 硬约束冲突不能发布。 |
| SCH-AC-02 | 每条冲突包含原因、对象和调整建议。 |
| SCH-AC-03 | 人工调整后实时重新检查冲突。 |
| SCH-AC-04 | 发布前可按教师、班级和教室预览。 |
| SCH-AC-05 | AI / 求解器不能自动发布课表。 |
| SCH-AC-06 | 调课与代课保留原安排、新安排、原因和操作人。 |

## 7. 开放决策

目标学校节次、硬软约束、走班、单双周、场地、教师偏好、候选评价和通知规则均待专题评审。

## 数据责任与选择型字段合同

- 权威对象：`DAT-SCH-01` 至 `DAT-SCH-04`；排课输入引用 ORG-001 学期、班级、课程、教师、任课和场地主数据。
- Owner 边界：教务对约束、候选选择、正式课表和变更负责；求解器与 AI 只产生候选。
- 选择型字段：`SCH-F001` 至 `SCH-F012`；未确认的石家庄学校规则保持学校配置来源，不伪造默认硬软性质。
- 中央事实源：[数据 Owner 矩阵](../07-structured-requirements/data-ownership-matrix.md)；[字段与选项字典](../07-structured-requirements/field-option-catalog.md)。

## 数据流转合同

- 参与 Flow：`DF-201` 排课输入到候选与正式课表，`DF-202` 调课 / 代课到新版本与通知。
- 输入：ORG 主数据、`DAT-SCH-01` 和当前 `DAT-SCH-03`；输出：`DAT-SCH-02/03/04`、教师 / 班级 / 教室视图和通知结果。
- 输入或约束变化使旧候选失效；硬冲突阻断发布；通知部分失败只重试失败接收对象。
- 中央事实源：[跨模块数据流转合同](../07-structured-requirements/data-flow-catalog.md)。
