## 2. 关键业务规则

1. 只有已发布结果才能进入反馈与订正。
2. 学生只查看本人原答案、教师确认分、公开反馈和学校允许开放的答案 / 解析。
3. 每道错题展示错误原因、对应知识点、教师公开评语和下一步动作。
4. 提示分层：方向提示、关键步骤提示、完整解析；可见层级由教师在作业规则中确定。
5. 教师要求独立完成时，订正前不展示完整答案。
6. 每次订正形成独立 Attempt，保留答案、时间、提示使用情况和结果。
7. 订正通过不覆盖首次成绩；结果进入 INS-001 作为新证据。
8. 客观题可按规则生成通过建议；主观题和低置信结果进入教师复核。
9. 错题从错题本移除仅表示学生不再收藏，不删除历史证据。
10. 成绩修正由 PUB-001 完成，订正模块不能直接改发布分。

|---|---|

| 已关闭 | 教师关闭订正要求，只读历史 |

## 4. 需求章节

### 4.1 反馈详情与错题列表

- 作业摘要显示总分、发布 / 修正时间、待订正数量和教师公开总评。
- 错题列表按题号展示得分、错误原因摘要和订正状态。
- 点击进入错题详情，保留返回列表位置。

### 4.2 订正作答与提示

- 支持在线重新作答或按原题要求拍照上传。
- 每次打开提示都记录层级，但不用于惩罚学生。
- 提交前展示本次答案、提示使用和是否还有未完成订正。

### 4.3 订正结果

- 自动建议通过的客观题在学校规则允许时可直接显示结果；其他进入待复核。
- 未通过时说明下一步，不只显示红色错误。
- 通过后显示“已形成新的学习证据”，不宣称“已经完全掌握”。

### 4.4 错题本

- 支持按学科、知识点、错误类型和订正状态筛选。
- 错题详情引用原始题目与历史订正；不复制出与原记录脱节的题目版本。

## 5. 权限与异常

| 场景 | 处理 |
|---|---|
| 结果尚未发布 | 不展示反馈页 |
| 教师修正成绩 | 展示最新分与更新时间，订正记录保持 |
| 题目或图片加载失败 | 保留文字和重试入口，不丢订正草稿 |
| 教师关闭订正 | 学生只读查看历史与原因 |
| 任课教师变更 | 新教师按权限处理待复核，原操作人保留 |

## 6. 验收与评估

| ID | 验收标准 |
|---|---|
| APP2-AC-01 | 未发布结果无法进入反馈与订正。 |
| APP2-AC-02 | 学生只能查看本人答案和公开反馈。 |
| APP2-AC-03 | 独立完成题在订正前不展示完整答案。 |
| APP2-AC-04 | 每次订正形成独立版本并可追踪提示使用。 |
| APP2-AC-05 | 订正结果不覆盖首次成绩。 |
| APP2-AC-06 | 主观题和低置信订正进入教师复核。 |
| APP2-AC-07 | 订正通过只形成新证据，不直接宣称完全掌握。 |
| APP2-AC-08 | 错题本移除不删除历史证据。 |

评估指标：反馈查看到订正转化率、订正完成率、再次订正率、教师复核时长、提示使用分布。

## 数据责任与选择型字段合同

- 权威对象：`DAT-APP2-01` 至 `DAT-APP2-04`；已发布反馈继承 PUB-001，订正作答由学生负责，订正判定由对应任课教师负责。
- 错题本和筛选分组是派生视图，不建立独立 Owner，也不删除历史证据。
- 选择型字段：`APP2-F001` 至 `APP2-F006`，覆盖学科、知识点、订正状态、错误类型、提示策略和教师判定。
- 中央事实源：[数据 Owner 矩阵](../07-structured-requirements/data-ownership-matrix.md)；[字段与选项字典](../07-structured-requirements/field-option-catalog.md)。

## 数据流转合同

- 参与 Flow：`DF-007` 生成反馈 / 错题，`DF-008` 处理成绩修正，`DF-009` 订正到新证据。
- 输入：`DAT-PUB-02/03`、`DAT-APP2-01/02` 和提示策略；输出：`DAT-APP2-03/04` 与新的 `DAT-INS-01`。
- 订正版本不覆盖首次作答；AI 建议不能直接形成通过；源成绩或知识点变化触发证据重新评估。
