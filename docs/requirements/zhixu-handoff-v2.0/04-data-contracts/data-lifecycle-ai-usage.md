# 数据生命周期、敏感级别与 AI 使用边界

## 生命周期策略

| Policy ID | 适用范围 | 写入规则 | 历史规则 | 保留 Owner | 到期 / 归档 |
| --- | --- | --- | --- | --- | --- |
| LIFE-001 | TENANT_CONFIGURATION | 仅学校管理员可通过受审计的配置变更写入，生效配置必须有明确版本。 | 每次生效保留前后版本、操作者和生效时间，不覆盖历史配置。 | ROLE-SCHOOL-ADMIN | 学校停用后按激活时配置的期限归档；期限未配置时禁止敏感数据能力。 |
| LIFE-002 | SCHOOL_YEAR_ORGANIZATION | 教务在对应学年内以生效日期维护组织关系，跨学年变化创建新事实。 | 已结束学年的组织版本只读，任课和班主任关系按有效期回放。 | ROLE-ACADEMIC | 学年结束后转历史只读，并按学校配置归档而不改写原关系。 |
| LIFE-003 | VERSIONED_TEACHING_FACTS | 草稿可修改；提交、确认或发布后只能创建新版本，不能覆盖已确认事实。 | 作业、提交、评分、反馈、证据和提升事实保留完整版本链及失效关系。 | ROLE-ACADEMIC | 学期结束后停止新增到该学期，历史版本按学校保留策略归档。 |
| LIFE-004 | IMMUTABLE_AUDIT_EVENTS | 审计事件仅允许系统追加，任何角色不得更新或删除已接受事件。 | 按事件时间、主体、动作、对象范围和结果保留不可变序列。 | ROLE-SCHOOL-ADMIN | 达到学校法定或制度保留期后执行受审计归档或销毁。 |
| LIFE-005 | TEMPORARY_AI_PREVIEWS | AI 可生成和刷新临时预览；未经授权用户确认不得转为业务事实。 | 仅保留任务状态、确认结果和必要审计摘要，临时内容不作为长期教学事实。 | ROLE-PLATFORM-OPS | 预览在配置的短期时限或上下文失效时自动过期并不可执行。 |
| LIFE-006 | REPORT_SUBSCRIPTIONS_RUNS_SNAPSHOTS | 订阅定义由创建者在授权范围内维护；每次运行和交付快照由系统追加。 | 订阅变更保留版本，运行记录和报告快照不可被后续数据刷新改写。 | ROLE-ACADEMIC | 停用订阅不再运行；运行记录和快照按学校报告保留期归档。 |
| LIFE-007 | CROSS_TERM_LEARNING_PATHS | 新学期追加新的证据、结论和计划版本，历史学期事实不回写。 | 跨学期路径保留来源学科、知识点版本、证据阶段和确认责任人。 | ROLE-ACADEMIC | 在学校配置的学生学习数据保留期内连续可读，到期后按主体范围归档或删除。 |
| LIFE-008 | EXPIRING_EXPORTS | 导出文件由一次受审计请求生成，生成后不可修改或扩大数据范围。 | 长期保留导出请求、权限判定和访问审计，不长期保留临时下载文件。 | ROLE-SCHOOL-ADMIN | 文件达到显式有效期后立即失效并删除；未配置保留期限时禁止敏感导出。 |
| LIFE-009 | IDENTITY_RELATIONSHIP_AND_DATA_RIGHTS | 身份、监护、学校数据授权与高影响事项必须通过独立关系或授权事实写入，任何职责不得合成关系。 | 保留授权来源、范围、期限、争议冻结、纠正与执行版本；彻底注销后删除可回查身份映射。 | ROLE-PLATFORM-GOVERNANCE | 按数据主体权利、来源权利、争议保全和法定留存逐对象删除、限制、去标识或保留。 |
| LIFE-010 | SHORT_LIVED_ASSISTANCE_AND_DEVICE_SESSIONS | 任务辅助与共享设备会话只能在当前已授权任务和显式期限内创建，不能扩大到账户或完整历史。 | 仅保留必要的参与、范围、开始、结束、清理结果与审计摘要，不保留可复用的敏感会话内容。 | ROLE-SCHOOL-ADMIN | 任务结束、身份切换、退出或会话超时立即失效并清理产品可控制状态。 |

## 敏感级别

| Sensitivity ID | 名称 | 处理规则 |
| --- | --- | --- |
| S1 | 公开信息 | 仅包含学校批准公开的非个人信息，可公开展示但仍需防止内容被未授权篡改。 |
| S2 | 校内教学业务数据 | 仅在学校成员与业务授权范围内使用，导出和跨模块使用必须记录来源与用途。 |
| S3 | 未成年人个人与学习数据 | 最小必要访问、传输与存储加密、对象级授权和完整审计；禁止无授权外发或用于模型训练。 |
| S4 | 高敏身份与安全数据 | 凭据、认证因子、权限变更和安全审计严格隔离，默认不可导出，访问需加强认证与专项审计。 |

## 非功能门禁

| NFR ID | 要求 | Owner | 验证 |
| --- | --- | --- | --- |
| NFR-001 | 支持200名活跃试点学生；每班60个并发提交时不得丢失已被服务器接受的答案。 |  | 在试点数据规模下执行每班60并发提交压测，核对服务器回执与持久化答案逐项一致。 |
| NFR-002 | 在试点负载下，非 AI 列表和详情读取响应时间 p95 不超过2秒。 |  | 以试点并发和数据量压测非 AI 读取接口，分别统计列表和详情的服务端 p95。 |
| NFR-003 | 不含媒体传输的草稿保存确认响应时间 p95 不超过1秒。 |  | 分离媒体上传耗时后压测文本与结构化草稿保存，统计服务器确认 p95。 |
| NFR-004 | 每次提交最多支持12张图片、每张10MB，格式为 JPEG、PNG 或 HEIC；失败可断点重试且保留已成功部分。 |  | 覆盖数量、大小、格式、断点续传、单项失败重试和成功分片保留的边界测试。 |
| NFR-005 | App 在临时断网后保留文本草稿和媒体上传草稿；正常提交以服务器回执为准，弱网按时保护使用截止前服务端提交意图凭证、固定内容清单摘要和限定补齐窗口。 |  | 在编辑、上传、提交和凭证补齐阶段分别断网恢复，验证本地草稿、续传状态、固定清单约束、平台故障保护以及无回执不显示正常提交成功。 |
| NFR-006 | AI 任务采用异步处理、发布、争议纠正和有效性状态轴；AI 超时、失败或不可用时不得伪造结果、改变按时事实或绕过必要门禁。 |  | 注入 AI 超时、失败、不可用、结果质疑和安全检查失败，验证状态可见、人工例外复核可进入、历史版本保留且未通过门禁的结果保持未发布。 |
| NFR-007 | Web 支持当前及上一个主要版本的 Chrome 和 Edge；App 产品支持 iOS 16+ 与 Android 10+。 |  | 在支持矩阵的最低版本、当前版本及上一主要浏览器版本执行核心场景回归。 |
| NFR-008 | 授权拒绝、版本冲突、审计失败和部分成功必须具有彼此不同且可观测的结果。 |  | 分别触发四类结果，验证接口代码、用户状态和可观测事件能够无歧义区分。 |
| NFR-009 | 精确保留期限是学校激活时由学校管理员负责的必填配置；未设置时阻断敏感导出和 AI 使用。 | ROLE-SCHOOL-ADMIN | 在保留期限缺失和已配置两种激活状态下验证门禁，确认不存在隐式默认期限。 |
