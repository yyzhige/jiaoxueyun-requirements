# 跨模块数据流转合同

Flow ID 描述业务对象与版本如何产生、确认、传播、失效和补偿，不代表具体 API、数据库表或消息队列。

## 1. 主闭环

学校与组织基线 -> 作业发布 -> 学生提交 -> AI 初评 -> 教师复核 -> 成绩反馈发布 -> 学生订正 -> 学习证据 -> 个性化提升 -> 学生执行 -> 报告与长期路径。

## 3. Flow 验收规则

1. 每个 Flow 必须声明源版本、目标版本、业务幂等键和下游失效规则。
2. AI、系统批处理和报表只能产生建议、草稿、派生视图或快照；正式教学判断由有权角色确认。
3. 对象级部分成功必须可重试，已成功对象不得重复写入。
4. 权限、审计、上下文或版本校验失败时，高风险写入失败关闭。
5. 通知失败不回滚源业务事实，但必须记录投递失败和重试入口。
