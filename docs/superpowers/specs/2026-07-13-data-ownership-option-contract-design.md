# 知序需求包数据责任与选项合同设计

## 1. 问题

当前需求包已经描述页面、业务对象、角色权限、状态和验收，但仍缺少两类可交付合同：

1. 谁对一类数据的正确性、变更规则和生命周期承担最终责任。
2. 哪些字段是选择型控件，以及选项从哪里来、如何联动、失效后如何展示。

没有这两类合同，原型只能临时猜测控件，前后端会分别发明枚举，测试也无法判断选项是否完整。

## 2. 第一性原理

### 2.1 数据责任

1. 数据的价值来自它支持的业务判断，因此最终 Owner 必须是能对该业务判断负责的人类角色。
2. AI、缓存、聚合视图和导出文件不能成为业务数据 Owner。
3. 每个可独立变更、确认或发布的业务对象必须有且只有一个最终 Owner。
4. 字段默认继承对象 Owner；只有来源、隐私或确认权不同的字段才单列例外。
5. “可以查看”“可以操作”和“对数据负责”是三个不同概念，不能用权限矩阵代替 Owner 矩阵。
6. 班主任的全科查看与协调权不等于跨学科数据修改权；学科判断仍由对应任课教师负责。

### 2.2 选项合同

1. 只要用户不能自由输入任意值，该字段就需要选项合同。
2. 选项合同必须同时定义业务值、显示文案和来源，不能只写页面上的中文标签。
3. 固定枚举、学校主数据、当前权限范围和运行时派生结果必须明确区分。
4. 下拉、单选、多选、级联选择、自动完成和分段控件共享同一选项合同，但控件形态可以不同。
5. 历史记录必须保留当时值；选项停用后不能让历史数据变成空白或被静默替换。
6. 级联字段必须定义父字段、重置规则、加载失败和无可选项状态。

## 3. 方案选择

### 方案 A：逐 PRD 独立补齐

优点是模块阅读直接。缺点是学校、学期、班级、学科、状态等选项会在多份文档重复，容易漂移。

### 方案 B：只建立中央数据字典

优点是事实唯一。缺点是模块 PRD 无法快速判断页面需要哪些字段和局部规则。

### 方案 C：中央事实源加模块薄引用

中央文件定义 Owner 和 Option Set，模块 PRD 引用对应 ID，只补页面特有的默认值、联动和权限差异。

采用方案 C。它同时满足 DRY、可追溯和模块可读性。

## 4. 交付结构

### 4.1 数据 Owner 矩阵

文件：`07-structured-requirements/data-ownership-matrix.md`

每个对象至少包含：

| 属性 | 含义 |
|---|---|
| Data ID | 稳定的数据对象编号 |
| 业务对象 | 用户可理解的对象名称 |
| 最终 Owner | 对正确性与业务规则负责的唯一角色 |
| Steward | 日常维护与质量处理角色 |
| 产生者 | 创建原始记录的人或系统 |
| 确认 / 发布者 | 让数据正式生效的角色 |
| 事实源 | 该数据的权威来源 |
| 主要消费者 | 使用该数据的模块或角色 |
| 关键边界 | 不允许越过的责任边界 |

### 4.2 字段与选项字典

文件：`07-structured-requirements/field-option-catalog.md`

每个选择型字段至少包含：

| 属性 | 含义 |
|---|---|
| Field ID | 模块内稳定字段编号 |
| 页面 / 场景 | 字段出现位置 |
| 字段 | 用户可见名称 |
| 控件 | 单选、多选、级联、自动完成、分段等 |
| Option Set | 复用的选项集合编号 |
| 来源 | 固定枚举、学校主数据、权限范围或派生结果 |
| 必填 / 默认 | 空值与初始行为 |
| 联动与权限 | 父字段、重置和可见范围 |
| 历史 / 失效 | 已停用选项的展示与新建限制 |

## 5. 模块回填规则

1. 19 份 PRD 都增加“数据责任与选择型字段合同”章节。
2. 章节只引用 Data ID 和 Field ID，不复制中央选项值。
3. APP-001、SCH-001、AI-001、CLI-001 补充缺失的字段合同入口。
4. 模块的权限矩阵继续负责“谁可以做什么”；Owner 矩阵负责“谁最终负责”。
5. 状态枚举继续以 `core-object-state-model.md` 为跨模块事实源，字段字典引用而不重复创造同义状态。

## 6. 就绪标准

需求包只有同时满足以下条件，才可以进入完整 HTML 原型与接口 Mock 阶段：

1. 每个业务对象都能解析到唯一最终 Owner。
2. 每个页面中的选择型字段都有 Field ID 和 Option Set。
3. 每个 Option Set 都有稳定 code、显示值、来源和失效策略。
4. 每个级联字段都有父级、清空和无数据规则。
5. 产品评审清单能够逐模块检查上述合同，而不是只标记“字段：有”。
